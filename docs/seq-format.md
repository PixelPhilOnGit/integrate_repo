# `.seq.json` 格式（手写 / 让 AI 生成都看这份）

**一张顺序图 = 一个 JSON 文件**，扩展名 `.seq.json`，放在顺序图模块选的那个工作区目录里。
没有数据库、没有云端 —— 改文件就等于改图，图改了就等于改文件。

> 这份文档是**给 AI 和人看的契约**。下面那个例子是**真的会被解析**的：
> `tests/unit/seq-format-doc.test.ts` 会把本文里第一个 JSON 代码块抽出来解析一遍，
> 所以它不会和代码漂移。

## 一个完整的例子

```json
{
  "schemaVersion": 1,
  "title": "登录流程",
  "participants": [
    { "id": "user", "kind": "actor", "name": "用户", "x": 120 },
    { "id": "web", "kind": "boundary", "name": "浏览器", "x": 320 },
    { "id": "api", "kind": "control", "name": "服务端", "x": 520 },
    { "id": "db", "kind": "database", "name": "数据库", "x": 720 }
  ],
  "messages": [
    { "id": "m1", "kind": "sync", "from": "user", "to": "web", "label": "输入账号密码", "y": 140 },
    { "id": "m2", "kind": "sync", "from": "web", "to": "api", "label": "POST /login", "y": 200 },
    { "id": "m3", "kind": "sync", "from": "api", "to": "db", "label": "查用户", "y": 260 },
    { "id": "m4", "kind": "return", "from": "db", "to": "api", "label": "用户记录", "y": 320 },
    { "id": "m5", "kind": "return", "from": "api", "to": "web", "label": "200 + token", "y": 380 }
  ],
  "activations": [
    { "id": "a1", "participant": "api", "startMessageId": "m2", "endMessageId": "m5" }
  ],
  "notes": [
    { "id": "n1", "text": "token 有效期 2 小时", "x": 560, "y": 420 }
  ],
  "theme": { "id": "light", "name": "浅色", "mode": "light" }
}
```

## 字段

顶层（除 `title` 外都可以省）：

| 字段 | 说明 |
| --- | --- |
| `schemaVersion` | 现在是 `1`。写错会被迁移逻辑兜住，但建议照写 |
| `title` | 图的标题（顶栏和文件名之外的展示名） |
| `participants` | 参与者数组（下面那张表） |
| `messages` | 消息数组 —— **先想清楚顺序，坐标要跟着顺序走** |
| `activations` | 激活条（那条竖直的窄条，表示「正在执行」） |
| `notes` | 贴纸注释 |
| `theme` | 配色。**省了就用默认的浅色**，一般不用写 |

`participants` 里每一项：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | ✅ | 自己起，**全文件唯一**。消息靠它引用 |
| `kind` | | `actor`（人形）/ `object` / `boundary` / `control` / `entity` / `database`。默认 `object` |
| `name` | | 显示名。默认「未命名」 |
| `alias` | | 消息里显示的短名（比如 `用户` → `User`）。不填就用 `name` |
| `x` | ⚠️ | **生命线的横坐标**。不写就是 0（全叠在左边缘） |

`messages` 里每一项：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | ✅ | 自己起，全文件唯一 |
| `from` / `to` | ✅ | **必须是存在的参与者 id** —— 指向不存在的会被**整条丢掉** |
| `kind` | | `sync`（实线箭头）/ `async`（开口箭头）/ `return`（虚线）/ `self`（自调用，`from` 和 `to` 写同一个 id）。默认 `sync` |
| `label` | | 消息文字。默认空 |
| `seq` | | 显式序号。**不写就按纵向顺序自动编号**，所以一般不用写 |
| `y` | ⚠️ | 箭头的纵坐标。不写就是 0（全叠在一起） |

`activations`（可选）：`id`、`participant`（哪条生命线）、`startMessageId`（哪条消息触发的）、
`endMessageId`（可选，不写就延伸到下一个激活条或图底部 —— 那种语义是「还在执行中」）。

`notes`（可选）：`id`、`text`、`x`、`y`。

## 坐标怎么给（唯一需要算的东西）

图的排版**不做自动布局**：坐标就是文件里的值。按这个来就不会难看：

- **参与者的 `x`**：从左到右递增，间距 **180**（例子：120 / 320 / 520 / 720）
- **消息的 `y`**：从上到下递增，间距 **60**，第一条从 **120 或 140** 开始

自调用（`self`）建议间距给大一点（80+），它要画一个折回来的小方框。

## 三条不变量（写错了会看得出来）

1. **`messages` 的数组顺序必须和 `y` 一致**（从小到大）。顺序 = 逻辑顺序 = 视觉顺序，
   加载和每次编辑都会按 `y` 重排；反过来写虽然会自动排序，但读文件的人（和你自己）
   会更费劲。参与者按 `x` 同样处理。
2. **`from` / `to` 必须指向存在的参与者**。指向不存在的，那条消息会被**静默丢掉**。
3. **id 不能重复**（参与者内部、消息内部各自唯一）。重复的参与者会被丢掉。

## 手写错了会怎样

解析是**宽容**的：认不出来的元素**单独丢掉**，不会让整张图打不开；缺 `kind`/`name`/`label`
都有默认值。但两件事不会替你兜：

- **`x` / `y` 缺省是 0** → 全叠在一起（图能开，但看着像坏了）；
- **悬空引用** → 那条消息直接没了。

## 给 AI 的提示词（可以直接粘给窗格里的 Claude Code）

> 读一下 `docs/seq-format.md`，按那个格式把「登录流程」画成
> `D:\work\xxx\login.seq.json`：参与者是 用户 / 浏览器 / 服务端 / 数据库，
> 消息从上到下依次是：输入账号密码 → POST /login → 查用户 → 返回用户记录 → 200 + token，
> 服务端那条从 POST 开始到 200 结束挂一个激活条。
> 坐标按文档里的建议给（参与者 x 从 120 起每 200 一个，消息 y 从 140 起每 60 一条）。

写完**不用重启应用**：切到顺序图模块、或者文件树里点一下刷新就能看到。
